# 双人房间

[English](coop.md)

> 双人模式和单人模式一样跟随 `agent.language`：提示词、提示信息和界面都可以是英文或中文。
> 房间同样用 Murea 服务拍摄；同一场景里，每一轮都接着上一段视频往下拍。

在 `config.yaml` 里设置 `mode: coop`，网页打开后显示双人大厅，不再是单人界面。
双人模式（最多 4 人）下，所有玩家共用一个世界：每人写下自己的角色做什么，每一轮把所有人的动作一起拍成**一段**视频。

## 房间

| 类型 | 玩家 | 说明 |
|---|---|---|
| `local` | 2 个席位，一个人 | 你在同一页面上填写 A、B 两个角色的动作，适合一个人先试。没有邀请链接，也没有 AI 队友。 |
| `online` | 2–4 人 | 其他人通过邀请链接或 12 位邀请码加入。房主可以添加 AI 队友。 |

每位玩家绑定一个角色：上传参考图，或由房间生成一张（随机生成或按描述生成）。
玩家自己要求生成的形象在采用之前只是预览，因此生成失败或太慢都不会替换已有角色。
房间还会为空席位和 AI 队友生成默认形象；只有席位上仍没有自己的图片时，才会绑定它们。

房主还可以设置两项共享资产，都是可选的：

- **场景**：一张空的环境图，不含人物和生物。
- **BOSS**：一只非玩家生物，有自己的参考图。它不占席位，也不提交动作。

视频模型最多接收 5 张参考图，因此有 BOSS 时，房间最多容纳 3 位玩家（为场景保留一张）。

## 一轮的完整流程

1. **序章。** 所有角色都绑定后，房主开启冒险。服务端根据世界设定和已采用的资产，拍一段简短的序章视频（`coop.opening_seconds`）。玩家不需要为序章提交任何内容。
2. **资产提取。** 序章拍完后，评审读取它的关键帧。对于没有手动设置的场景或 BOSS，评审提取画面中**真实可见**的内容，并生成一张固定参考图。只被提到、或在画面中看不清的 BOSS 不会被登记。
3. **预告与建议。** 规划器写出 BOSS / 环境接下来会做什么，以及一个共同目标，再为每位玩家建议一个动作。这只是计划，不是事实：在视频确认之前，它不会写入世界。
4. **动作。** 每位玩家提交一个动作（或采用建议）。队友还在输入时，动作已在后台翻译成英文。
5. **拍摄。** 最后一位玩家提交后，服务端冻结一份不可变的房间快照，并编排出一条时间线：每位玩家的动作、世界事件，以及每张参考图稳定的 `<Subject N>` 编号。整支队伍只发送一次视频请求。
6. **观察。** 视频保存后，观察器读取它的关键帧，记录实际发生了什么：环境、BOSS、每个角色最后可见的状态、故事阶段，以及预告是否成真。只有观察结果才会成为事实。

参考图组合不变时，每段视频都从上一段的 latent 接着拍。
手动修改资产（上传、采用预览、编辑描述、移除、更换角色）会让续写链重新开始一次。

日志：`coop_forecast_started`、`coop_scene_plan_compiled`、`video_request`、`video_result`、`coop_story_observation`、`coop_done` 和 `coop_continuation_decision`（记录续写链为何保留或中断）标记各个阶段。

## 故事大纲

拍摄序章时，规划器写出本章目标和 3–5 个阶段，每个阶段都有一个可以由画面确认的完成条件。
进度在同一次观察调用中判断，只依据关键帧证据：观察不清或缺失记为未知，绝不算作失败。
明显停滞两轮后，预告必须尝试新的路线。
每五轮根据实际发生的情况修订一次大纲；所有阶段完成后进入下一章。
详见 [coop-story-director_zh.md](coop-story-director_zh.md)。

设置 `COOP_STORY_ENABLED=0` 可以关闭大纲，只保留预告 / 建议循环。

## AI 队友

在联机房间里，房主可以添加 AI 队友（持斧战士、守护者、法师）。每个 AI 队友都有自己的形象，并占一个席位。
所有真人玩家提交后，AI 队友在一次模型调用中写出与之配合的动作，然后这一轮开始。
如果所有真人都原样采用了建议，AI 队友也直接采用自己的建议，不调用模型，这样提前拍好的视频（`coop.speculative_video`）就能用上。
没有新的真人动作时，AI 队友绝不会自己开始一轮。

`coop.ai_mode: offline` 用简单规则代替模型，用于在没有模型的情况下测试。
如果整个实例都要离线运行，还需要同时关闭生成。

## 沉浸模式

沉浸模式自动采用每位玩家的建议，让故事持续推进。
当前视频播放时，下一段可能已经在生成，但播放器只在当前视频播完后才切换，所以故事永远不会跑到播放进度前面。
退出（按钮、Esc、离开房间）会取消待开始的一轮；已经提交生成的视频会保留。

## 配置

`config.yaml`：

| 键 | 默认值 | 含义 |
|---|---|---|
| `coop.public_url` | `""` | 邀请链接使用的公开地址。留空时使用浏览器当前的地址。 |
| `coop.opening_seconds` | `6` | 序章视频的时长。 |
| `coop.min_seconds` / `coop.max_seconds` | `6` / `15` | 每轮时长的范围，以 2 秒为步长，直到上限。时长按动作估算：互不依赖的动作同时进行，有先后依赖的动作时间相加。一轮就是一段视频；需要超过上限的一轮会被压缩进去。Murea-Fast 最长 20 秒（单卡服务为 5 秒），完整版模型最长 15 秒。 |
| `coop.speculative_video` | `true` | 在玩家还在决定时，先拍推荐动作的视频。所有建议原样采用时立即播放；有任何改动就取消。每轮多生成一段视频。 |
| `coop.ai_mode` | `llm` | AI 队友使用 `llm` 或 `offline`。 |
| `coop.ai_model` | `""` | AI 队友使用的模型；留空时使用 `llm.models.agent`。 |

环境变量开关，主要用于测试：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `COOP_GENERATION_ENABLED` | `1` | 设为 `0` 时仍可使用房间、上传和预览，但不会生成视频。 |
| `COOP_AUTO_GENERATE` | `1` | 所有人准备好后立即开始这一轮，并生成默认形象。设为 `0` 时需要房主手动开始，也不生成默认形象。 |
| `COOP_INTRO_ENABLED` | `1` | 预告和建议。设为 `0` 时也会关闭故事大纲；序章要等预告完成，所以任何房间都无法开始。 |
| `COOP_ACTION_PREFETCH` | `1` | 队友还在输入时就翻译每个动作。 |
| `COOP_RECOMMENDATION_PREFETCH` | `1` | 提前为建议动作准备完整的 prompt。设为 `0` 时也会关闭 `coop.speculative_video`。 |
| `COOP_STORY_ENABLED` | `1` | 章节大纲和进度跟踪。 |
| `COOP_PARALLEL_ROUNDS` | `4` | 最多允许几个房间同时进行一轮（1–4）。 |

角色形象、场景和 BOSS 都用配置的 `image.provider` 生成。

## 代码

| 路径 | 内容 |
|---|---|
| `murea_agent/coop/room.py` | 房间、席位、锁、重启后的恢复 |
| `murea_agent/coop/loop.py` | 通过 Agent 可追踪的回合循环跑完一轮 |
| `murea_agent/coop/generation.py` | 联合镜头规划、视频请求 |
| `murea_agent/coop/action_text.py` | 动作和旁白的翻译修复 |
| `murea_agent/coop/scene_plan.py` | `ShotCompiler`：时间线和主体编号 |
| `murea_agent/coop/duration.py` | 每轮时长 |
| `murea_agent/coop/intro.py` | 预告和建议 |
| `murea_agent/coop/prefetch.py` | 为建议动作提前准备 prompt 和视频 |
| `murea_agent/coop/observation.py` | 每段视频实际拍出了什么 |
| `murea_agent/coop/story.py`、`chapter.py` | 章节大纲、进度和下一章 |
| `murea_agent/coop/immersive.py` | 沉浸模式 |
| `murea_agent/coop/assets.py`、`portrait.py` | 场景 / BOSS 资产和角色形象 |
| `murea_agent/coop/ai.py` | AI 队友 |
| `app/api/routes/coop.py` | HTTP API |
| `frontend/src/coop/` | 大厅、房间和沉浸模式界面 |

测试：`python tests/run_all.py` 会用双人模式的服务配置运行双人测试（`tests/test_coop*.py`）：离线运行，使用假模型和临时数据目录。
