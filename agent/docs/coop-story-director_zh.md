# 合作故事规划与观察反馈

[English](coop-story-director.md)

本文说明双人房间如何规划剧情，以及如何用实际拍出的画面核对规划。玩法和设置见[双人模式](coop_zh.md)。

## 规划的三个层次

- **章节大纲**：拍摄序章时，规划器在后台写出本章目标和各个阶段。之后每五轮根据实际发生的事修订大纲，
  本章完成后再规划下一章。
- **预告**：每一轮的预告为当前阶段提出 2–3 个短期小目标，每个都包含前置条件、协作分工、
  画面上可见的完成条件和受阻时的备选方案。
- **动作建议**：给玩家的动作建议只执行计划的第一步。后续步骤只是候选，不会进入本轮动作，也不会被当作已发生的事实。

## 观察反馈

视频生成后，独立的观察器用画面核对实际采用的预告、玩家动作和第一个短期小目标。
阶段完成和小目标完成分别记录，都需要本轮关键帧作为证据。缺少观察不等于失败。
已确认完成的小目标不能再次成为同一阶段计划的第一步。

## 当前状态

`story_state.facts` 按实体与属性保存状态、证据、节点和轮次，例如
`object:stone_gate.passage`、`boss.posture`、`<user_id>.location`。
新观察替换同一字段的旧值，未出镜的字段保留；过去的变化在按轮保存的观察记录中查询。
规划器读取当前状态和最近八轮观察，完整历史不再重复嵌入当前状态。
手动修改资产后，旧构图的结构化状态失效；迟到的旧观察只记录历史。

## 并行生成与校正

当前视频生成时，下一轮预告仍在后台草拟。最新观察、大纲修订以及推荐预生成入口会检查建议依据。
同一阶段内的通路变化、位置变化、动作结果和剩余目标也会参与检查。
后台校正先判断是否保留方案、只改动作、或重写预告与短期目标，最后原子发布。

已编辑/采纳的玩家动作、已开始渲染的下一段视频保持其采用的方案。
尚未提交的推荐视频可以先完成动作编排，在提交前为观察和校正合计保留至多六秒窗口。
观察完成会主动恢复，超时也有一次性唤醒，不依赖增加轮询。
校正使用独立线程池；超时后释放规划锁，迟到结果不能覆盖后续工作。
退出沉浸模式后，已有的暂停预生成标记继续生效。

## 重复与停滞

建议记录实际目标、路径、战术和协作职责；只有玩家真正采用的建议才计入战术历史。
正在取得进展的同类动作可以继续。明确受阻或连续两次观察无进展时，立即调整短期计划，完整大纲仍保持五轮周期。
停滞场景额外做一次语义核验，并最多修正一次对应部分；核验或修正服务不可用时保留已验证的可执行方案。
观察不清时优先安排容易确认结果的单一动作，不编造成功或失败。

大纲页将「行动安排」与「全局大纲」分区展示。行动安排按「本轮尝试」「后续待确认」区分，
条件和备选方案可展开；阶段编号仅用于全局大纲。行动日志保留校正范围、战术核验和失败降级记录。

短期计划的展示字段要求直接用故事语言（`agent.language`）生成，只有 id 与枚举使用英文。
在中文房间里打开大纲时，旧存档的全英文说明通过 `/story/display-zh` 按需批量翻译并缓存，
普通中文内容不调用模型。该请求只产生展示文案，不修改原始大纲、采用的计划、
观察完成条件、房间修订号或推荐视频缓存，也不阻塞预告、建议和视频生成。
翻译失败时大纲仍可查看，提供重试入口；不为了翻译而重新编排剧情。
